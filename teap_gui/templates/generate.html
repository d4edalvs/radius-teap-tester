Network Access Device
Identifies the access device, so it is normally the same for every session. Supports per-session templates: $MAC$ $IP$ $SESSION$ $INDEX$ and uc() lc() hex() rand(a..b) pad(x,n), e.g. uc(hex(rand(4096..65535)))/uc($MAC$)/uc(hex(rand(4096..65535))) to simulate many devices.
Some servers look the device up by this instead of by address. Omitted if blank.

MAC & IP Addresses
One per session, sent as Calling-Station-Id: the client device's MAC, which the server logs and can match in policy. Also available as $MAC$ in attribute templates.
The first three bytes, to make the random MACs look like one vendor's devices. Blank gives fully random, locally administered MACs (02-…).
One MAC per line. Sessions take them in order and start again from the top if there are more sessions than lines.
The client device's own address, sent as Framed-IP-Address in accounting and available as $IP$ in templates. Not the NAS address — that is Source IP under Network Access Device.
Each session gets a random host address from this subnet. Blank sends no endpoint IP at all.
One IP per line, used in order and repeated from the top if there are more sessions than lines.
TEAP Parameters

Configure each leg separately. Setting both exercises EAP chaining, including a machine certificate with a user password.

Derived uses the UPN, SAN email or CN for the user, and host/ plus the SAN DNS for the machine. Anonymous sends anonymous in the clear. Password legs always name their own identity, since there is no certificate to read it from.
Encrypted at rest, like a shared secret.
